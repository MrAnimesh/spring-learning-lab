1. SpringApplication.run(...); (Without assigning)
    This is the default code generated by Spring Initializr.
    When to use it: 99% of the time, especially for web applications (REST APIs, MVC apps).
    Why: In a typical Spring Boot app, you don't need to manually interact with the Spring container in your main method. Once the app starts, Spring takes over completely. It automatically wires your controllers, services, and repositories together using @Autowired or constructor injection, and listens for HTTP requests. You never need to touch the ApplicationContext directly.

2. ApplicationContext context = SpringApplication.run(...);
    This captures the Spring container into a variable so you can interact with it directly inside your main method.
    When to use it: When you are building a Command Line (CLI) application, a batch script, or when you are debugging.
    Why: Because it allows you to manually ask Spring for specific beans and execute them right there in the main method, rather than waiting for a web request to trigger them.

4.  ApplicationContext is Spring's higher-level IoC container used in normal Spring applications.
    It provides bean-management capabilities and additionally integrates features such as events,
    resources, environment and profiles, internationalization, and automatic registration of Spring infrastructure components.

5.  BeanFactory is Spring's fundamental IoC container abstraction. It is responsible for creating, configuring,
    resolving dependencies for, managing, and retrieving beans.

6.  ApplicationContext normally pre-instantiates non-lazy singleton beans during context initialization,
    whereas a basic BeanFactory doesn't automatically pre-instantiate them in the same way.
    BeanFactory is lazy; ApplicationContext eagerly creates singleton beans.

7.  BeanFactory is the basic bean-management engine. ApplicationContext is the full-featured Spring container
    built on top of those capabilities.

8.  The Spring IoC container is the runtime component responsible for creating, configuring, wiring, and
    managing Spring beans. ApplicationContext is the commonly used IoC container in Spring.

9.  Spring normally injects field dependencies before the bean is used, so field injection works. Constructor
    injection is preferred because it makes required dependencies explicit and guarantees the object cannot be
    constructed without them. It also allows final fields and makes the class easier to instantiate and test
    without Spring.

    Field injection guarantee:
    "Trust Spring to make this object valid."

    Constructor injection guarantee:
    "Java won't let you create this object
    without its required dependencies."


 10.If there is one implementation of an interface, Spring injects it by type. If multiple implementations exist,
    we resolve the ambiguity using @Qualifier or @Primary. Loose coupling comes from the dependent class relying on
    the interface rather than creating or depending directly on a concrete implementation.

11. IoC means we give the control of object creation, dependency management, and object lifecycle to the Spring
    container instead of managing those objects manually in our application code.

12. If using both @Primary and @Qualifier, then spring will consider @Qualifier one.
